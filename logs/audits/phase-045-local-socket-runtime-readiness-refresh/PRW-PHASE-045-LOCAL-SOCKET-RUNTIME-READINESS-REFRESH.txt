NEWLY ISOLATED PROVIDER-NEUTRAL GAP

Phase 011 read_frame() intentionally classifies EOF before all 24 header bytes as TruncatedHeader. That is correct for one requested frame, but a future multi-request connection loop needs a separate frame-boundary distinction:
- EOF before any byte of the next frame: clean peer close / normal connection stop;
- EOF after one or more bytes of the next header: truncated frame / protocol failure.

The repository does not yet expose that boundary distinction. Implementing it over generic std::io::Read is safe provider-neutral work and does not require a Unix socket, timers, credentials, filesystem mutation, or a syscall dependency.

SAFE NEXT STEP

Proceed with a focused pure generic-I/O Phase 046 that classifies clean EOF at a frame boundary separately from partial-header truncation while preserving the existing Phase 011 read_frame() contract.
