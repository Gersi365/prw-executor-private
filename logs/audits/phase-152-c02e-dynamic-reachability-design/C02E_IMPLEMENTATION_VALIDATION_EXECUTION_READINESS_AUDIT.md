## Finding 1 — prior C02e command examples omit mandatory `--locked`

The C02e validation tranche plan correctly requires zero dependency mutation in Tranche 1, but its focused and full-workspace command examples use Clippy/tests/build without `--locked`.

Phase 056 repository policy is more specific and authoritative:

- `cargo metadata --locked --no-deps --format-version 1` before build-oriented gates;
- Clippy with `--locked`;
- tests with `--locked`;
- build with `--locked`;
- formatting exempt because rustfmt does not resolve dependencies.

The standard Rust validation workflow implements those exact locked gates.

Therefore the omission in the earlier C02e plan is a readiness defect in command specification. It does not invalidate the two-tranche design, but future execution must not use the unlocked examples literally.

## Finding 2 — locked metadata preflight is required

Hashing manifests/lockfile before and after validation detects unexpected mutation after the fact, but Phase 056 additionally requires the committed lock graph to be proven satisfiable before build-oriented gates.

`cargo metadata --locked --no-deps --format-version 1` provides that fail-closed preflight.

If it fails, validation must stop rather than allowing Cargo to normalize or regenerate dependency state.

This is particularly important for Tranche 1 because any dependency-state change is outside its authority.

## Finding 3 — full workspace has native desktop prerequisites

The root workspace includes `apps/desktop`, whose manifest depends on GTK4 and libadwaita.

The standard Linux Rust workflow installs `pkg-config`, `libgtk-4-dev`, and `libadwaita-1-dev`, then records GTK/libadwaita versions before Rust validation.

A future full-workspace C02e validation performed on an unprepared Linux runner could therefore fail for environment reasons unrelated to C02e source.

The validation evidence must prove native prerequisites or classify their absence as environment/tooling failure before applying source corrections.

## Finding 4 — Tranche boundaries remain correct

No evidence justifies changing the existing tranche architecture:

- Tranche 1 validates current source with zero dependency mutation;
- Tranche 2 separately owns any test-only `prw-nat-traversal` dev-edge and Cargo lockfile materialization;
- production composition/runtime/network/protocol gates remain separate.

The corrective is therefore limited to execution-readiness and command authority.

## Failure classification impact

The readiness review sharpens future evidence classification:

- locked metadata/manifest-lock inconsistency -> dependency-state failure;
- missing GTK/libadwaita/pkg-config/toolchain component -> environment/tooling failure;
- rustfmt-only diff -> formatting defect;
- typing/lint/test failure after locked preflight and environment readiness -> source defect.

This prevents environment or dependency drift from being repaired through unauthorized C02e source changes.
