PURPOSE

Prevent the first OS worker-thread implementation from creating detachable or unaccounted session workers.

EVIDENCE

Rust 1.97.1 standard-library behavior establishes:

- dropping a normal JoinHandle detaches the associated thread and removes the ability to join it;
- Builder::spawn reports OS thread-creation failure through io::Result;
- std::thread::scope structurally prevents scoped threads from outliving the scope;
- a dropped scoped join handle is still joined before scope exit;
- Builder::spawn_scoped reports OS thread-creation failure through io::Result.

DECISION 1 — SCOPED SESSION WORKERS

Initial PRW Linux Agent session workers must be created only inside an enclosing std::thread::scope owned by the runtime orchestration call.

Unscoped std::thread::spawn / Builder::spawn session workers are not allowed in the initial runtime.

DECISION 2 — FALLIBLE SPAWN

Worker creation uses Builder::spawn_scoped so OS thread creation failure is a bounded error rather than a panic caused by thread creation itself.

DECISION 3 — CAPACITY BEFORE SPAWN

A Phase 075 worker permit is acquired before spawn and moves into the successful worker closure.

Spawn failure must release/recover the permit without leaving a half-registered worker or reusable ambiguous connection.

DECISION 4 — WORKER RESULTS REMAIN ACCOUNTED

Scoped lifetime prevents detached workers, but the final scheduler must also retain/reap scoped join handles so normal worker results, worker errors, and worker panics are explicitly classified.

The final runtime must not intentionally discard worker results by relying only on implicit scope joining.

DECISION 5 — STRUCTURAL SHUTDOWN ORDER

The runtime thread scope is the outer worker lifetime boundary.

Future shutdown ordering:

1. stop new accept/scheduling;
2. invoke a separately reviewed worker cancellation/connection-shutdown mechanism if required;
3. join/reap all remaining workers;
4. return from thread scope;
5. then clean listener/path/instance-lock state.

This phase does not implement the cancellation primitive.

NEXT SAFE IMPLEMENTATION

Phase 078 may implement one crate-internal scoped-worker spawn adapter that accepts an existing Scope, consumes one authenticated session and one worker permit, invokes the Phase 076 finite worker body exactly once, and returns the ScopedJoinHandle to the caller.

Tests must explicitly join every returned handle.

MUTATION STATEMENT

It spawns no thread, accepts no connection, processes no Request, activates no Agent bootstrap/systemd/service state, and changes no authentication/network/DNS/TUN/database/private-key/deployment state.
