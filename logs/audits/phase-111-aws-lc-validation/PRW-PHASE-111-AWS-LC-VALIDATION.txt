PUBLIC-KEY VALIDATION STRATEGY

The Phase 111 test harness uses aws-lc-rs ParsedPublicKey with ECDSA_P256_SHA256_ASN1, then re-serializes the parsed key as PublicKeyX509Der and requires exact byte-for-byte equality with the original PRW public-key bytes.

This canonical round-trip guard is deliberate. The provider may accept an alternate EC public-key representation such as a raw SEC1 point as an input convenience. PRW's locked control-plane profile does not. Requiring canonical X.509 SubjectPublicKeyInfo DER equality prevents provider input flexibility from silently broadening the PRW protocol contract.

The harness remains test-only and is located at:
crates/prw-control-plane/tests/phase111_aws_lc_identity_profile.rs

- use AWS-LC only for the device-identity role selected by the existing contract;
- keep transport cryptography separately selected;

- keep provider-specific code behind a narrow PRW abstraction;
- retain canonical SPKI enforcement rather than relying on provider parser flexibility;
- retain exact version/dependency pinning and locked CI;
- treat the native build and approximately 2.67 MB isolated footprint delta as an explicit engineering cost.
