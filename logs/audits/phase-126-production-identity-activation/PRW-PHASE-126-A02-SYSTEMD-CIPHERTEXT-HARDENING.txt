PURPOSE

Phase 126-A01 proved the creation-only provisioner and the public provisioning-to-runtime identity fingerprint binding. Before allowing production identity creation, A02 measured the exact metadata semantics of `/usr/bin/systemd-creds --user encrypt` when it writes directly to a caller-supplied output path on the real PowerCode host.

The objective was to avoid assuming that the system utility itself creates a final ciphertext file with PRW's required 0600 mode.

SOURCE HARDENING

A02 changed only the provisioning ciphertext handoff/validation logic.

The hardened production design now:
1. creates a unique same-directory temporary ciphertext pathname under the validated private credential directory;
2. invokes `/usr/bin/systemd-creds` directly, with the fixed logical credential name and private PKCS#8 only through child stdin;
3. directs systemd-creds to the temporary ciphertext pathname rather than capturing ciphertext through a PRW stdout buffer;
4. suppresses systemd-creds stdout/stderr from becoming a secret-bearing application surface;
5. zeroizes the PRW-owned plaintext PKCS#8 buffer immediately after the encryption child completes;
6. opens the created ciphertext using `O_NOFOLLOW` and read/write access;
7. requires the opened object to be a regular file owned by the current user;
8. rejects initial metadata carrying forbidden write/execute bits beyond the measured systemd-created read-only shape;
9. requires ciphertext size within the locked non-empty bounded range;
10. records device and inode identity through the opened descriptor;
11. hardens mode to exact 0600 through the already-open descriptor;
12. fsyncs the opened ciphertext;
13. re-reads descriptor metadata and requires same device/inode/owner/size with exact 0600 mode;
14. re-reads pathname metadata and requires it still names the same non-symlink device/inode;
15. atomically commits only with `RenameFlags::NOREPLACE`;
16. fsyncs the parent directory.

This removes any dependence on the system utility producing PRW's final required mode itself and closes a pathname-swap window between external command completion and final commit.

SECURITY PROPERTIES

The production provisioner still:
- uses no shell for secret-bearing operations;
- accepts no private key through argv/environment;
- persists no plaintext private-key file;
- offers no generic key import/export API;
- never overwrites an existing production identity;
- keeps the locked logical credential name compile-time fixed;
- does not perform enrollment or networking.

The intermediate ciphertext is encrypted material, not private-key plaintext, but it is nevertheless treated as sensitive state and is hardened to mode 0600 before becoming authoritative.
