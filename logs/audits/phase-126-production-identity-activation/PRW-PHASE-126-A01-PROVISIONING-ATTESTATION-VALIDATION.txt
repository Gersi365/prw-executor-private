A01 implemented the two prerequisites locked by Phase 126-A00 before any production key creation:

IMPLEMENTED SOURCE

A new workspace crate was added:
`crates/prw-device-identity-provisioning`

The provisioner is Linux-only and creation-only. It:
- derives the fixed production ciphertext destination from validated XDG state;
- derives the fixed production service drop-in destination from validated XDG config;
- rejects pre-existing ciphertext/drop-in state before key generation;
- generates ECDSA P-256 locally through the locked AWS-LC provider;
- validates the generated PKCS#8 v1 DER through the production signer boundary;
- computes SHA-256 over canonical X.509 SubjectPublicKeyInfo DER;
- invokes `/usr/bin/systemd-creds` directly through `std::process::Command` rather than a shell;
- uses the fixed logical credential name `prw.device-identity.private-key.v1`;
- places private PKCS#8 bytes only into the child stdin pipe;
- keeps PRW-owned plaintext bytes in zeroizing memory;
- commits encrypted state with no-replace semantics;
- exposes no existing-key import/export API;
- performs no enrollment/networking.

A narrow production binary was added:
`prw-device-identity-provision`

The CLI accepts zero user arguments only. A later A01 hardening commit made any argument fail closed before state mutation with:
`prw-device-identity-provision event=failed kind=invalid_arguments exit=failure`

The Agent startup boundary gained a public/non-secret attestation:
`prw-agent event=device_identity_loaded public_spki_sha256=<64-lowercase-hex>`

The attestation is emitted only after successful custody/signer loading and before the existing runtime lifecycle is entered.
The fingerprint is SHA-256 over the exact canonical SPKI DER returned by the signer.
The local IPC protocol remains version 1.0 and was not expanded solely for activation evidence.

The attestation is on stdout/journal rather than the existing bounded stderr terminal/failure channel, preserving the historical exact-one-stderr binary contract.
