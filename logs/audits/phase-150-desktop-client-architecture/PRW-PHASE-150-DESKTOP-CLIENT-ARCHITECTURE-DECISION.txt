LOCKED DESKTOP ARCHITECTURE:

PROCESS OWNERSHIP:
- Desktop UI is a separate unprivileged process.
- Headless PRW Agent remains independent of the UI lifecycle.
- Agent retains host runtime, policy, capability, private-key and privileged-operation authority.
- UI intent never grants capability and success is not shown before authoritative acknowledgement.

LOCAL IPC LOCK:
- Fixed endpoint: $XDG_RUNTIME_DIR/private-remote-workspace/agent.sock.
- Existing PRW runtime directory remains mode 0700.
- Existing Agent socket remains mode 0600.
- Existing Agent same-effective-UID SO_PEERCRED authorization remains mandatory before application-protocol reads.
- Existing authenticated connection/session and bounded request/response contracts remain authoritative.
- No TCP, abstract socket, /tmp, D-Bus, shell-command, or ambient-path fallback is authorized for desktop-to-Agent control.

DESKTOP IPC ADAPTER REQUIREMENTS:
- One narrow local IPC adapter isolates protocol mechanics from widgets.
- Fixed trusted endpoint only.
- Fail closed on unavailable or untrusted endpoint state.
- Bounded request identifiers and explicit request/response correlation.
- Transport, protocol, authorization, unsupported-command, conflict, and internal-Agent failures remain distinguishable.
- No arbitrary text-to-command conversion.
- Agent-side SO_PEERCRED remains mandatory and is not replaced by client validation.

INITIAL INFORMATION ARCHITECTURE:
- Overview.
- Machines.
- Sessions.
- Files.
- Transfers.
- Activity.
- Settings.
- Dark-first PRW styling may be used only through platform-compatible GTK/libadwaita semantics while preserving accessibility, keyboard/focus behavior, text scaling and native controls.

Phase 151 may implement the non-production Rust GTK/libadwaita desktop shell, deterministic application startup, navigation, presentation state, narrow local IPC client adapter, read-only GetAgentStatus and GetPrivateDnsConfig surfaces, explicit offline/error state, focused tests and CI/build validation.

REMOTE-DESKTOP BOUNDARY:
