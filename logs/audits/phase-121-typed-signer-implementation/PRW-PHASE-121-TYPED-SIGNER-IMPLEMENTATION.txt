LOCKED PRIVATE CREDENTIAL INPUT

Public constructor:
UbuntuEnrollmentSigner::from_pkcs8_v1_der(credential: &[u8])

Input bound:
1..=4096 bytes.

Before any signer object is returned, implementation requires:
- non-empty bounded input;
- aws-lc-rs parsing under ECDSA_P256_SHA256_ASN1_SIGNING;
- successful provider re-serialization as PKCS#8 v1;
- byte-for-byte equality between re-serialized canonical PKCS#8 v1 DER and supplied credential bytes.

This byte-equality requirement prevents the constructor from silently accepting another private-key serialization merely because the provider can parse it.

Explicit negative coverage includes:
- empty credential;
- oversized credential;
- truncated PKCS#8;
- P-384 PKCS#8 under the P-256 profile;
- RFC5915 EC private-key DER supplied instead of canonical PKCS#8 v1 DER.

All are rejected fail-closed.

PRIVATE MATERIAL LIFETIME

The signer constructor borrows the custody payload during parsing.

The signer object retains:
- the provider-owned EcdsaKeyPair;
- canonical public identity material.

The signer object does not retain a second PRW-owned raw PKCS#8 byte vector and exposes no private-key export accessor.

Therefore Phase 121 introduces no new long-lived PRW-owned mutable plaintext private-key buffer in production signer core. The future custody adapter remains responsible for owning and zeroizing the decrypted service-credential buffer after signer construction.

Debug implementation exposes only non-secret profile metadata and does not print private credential bytes or provider secret objects.

PUBLIC IDENTITY

After private-key parsing, the signer derives the public key through aws-lc-rs and serializes it as X.509 SubjectPublicKeyInfo DER.

The resulting PublicIdentityMaterial is locked to:
- DeviceIdentityAlgorithm::EcdsaP256Sha256;
- DeviceIdentityPublicKeyEncoding::SubjectPublicKeyInfoDer.

Reloading the same canonical PKCS#8 payload derives the same canonical public identity.

TYPED SIGNING API

The only public signing operation is:
UbuntuEnrollmentSigner::sign_enrollment_proof(request, challenge)

It accepts:
- &EnrollmentRequest;
- &EnrollmentProofChallenge.

It does not accept caller-controlled raw message bytes.

Before signing, it requires:
1. request.enrollment_id == challenge.enrollment_id;
2. request.public_identity == signer.public_identity;
3. successful construction of the canonical Phase 115 enrollment proof message.

Only after these typed checks does crate-private implementation call aws-lc-rs signing.

Successful output is the existing EnrollmentProofOfPossession type with:
- the request enrollment id;
- the exact challenge nonce;
- DeviceIdentityAlgorithm::EcdsaP256Sha256;
- DeviceIdentitySignatureEncoding::EcdsaSigValueDer.

REQUEST / KEY CONSISTENCY

A signer refuses to sign when the EnrollmentRequest public identity differs from the loaded private key's derived canonical public identity.

A signer also refuses to sign when request and challenge enrollment ids differ.

These checks occur before provider signing and prevent one loaded signer from acting as an oracle for a request claiming another device identity or another enrollment transaction.
