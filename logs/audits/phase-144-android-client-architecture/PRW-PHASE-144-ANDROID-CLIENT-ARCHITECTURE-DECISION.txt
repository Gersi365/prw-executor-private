LOCKED ANDROID ARCHITECTURE:
- Native Kotlin application.
- Jetpack Compose UI.
- Kotlin/Android owns Activity/Application lifecycle, Compose/ViewModel state, foreground/background policy, notifications, Android Keystore handles, Android permissions and platform service orchestration.
- Existing Rust PRW workspace remains authoritative for protocol/domain/security rules already validated through Phase 143.
- Android integrates those Rust components only through a narrow Android-specific native adapter; no generic eval/shell/filesystem/socket command bridge is authorized.
- Existing core workspace unsafe_code=forbid remains in force; any unavoidable JNI/native unsafe is isolated to the adapter boundary behind audited safe wrappers.

KEY CUSTODY:
- Android device and transport private keys are EC P-256 keys generated inside Android Keystore and are non-exportable.
- Public SPKI material may be exported for enrollment/registry use.
- StrongBox is requested when supported; fallback is normal Android Keystore, never plaintext/exportable PRW private-key storage.
- Typed PRW signing only; no generic arbitrary-message signing API.
- Key invalidation fails closed and requires recovery/re-enrollment.
- Device identity and transport identity remain separately rotatable.

TRANSPORT:
- Existing PRW QUIC v1 / TLS 1.3 / prw-mesh/1 / SPKI-SHA256 TransportIdentity profile remains authoritative.
- Android MUST NOT export a Keystore private key merely to satisfy the current disposable PrivateKeyDer helper.
- Phase 145+ must use a platform-backed signing path or equivalent audited integration that retains private signing in Android Keystore.
- No alternate Android-only PRW wire protocol is authorized.

EXECUTION MODEL:
- UI emits typed intents and observes immutable presentation state.
- A connection controller owns one explicit PRW connection state machine.
- A user-visible foreground service owns persistent active remote connectivity where Android policy requires it.
- No hidden always-on daemon and no boot-time remote activation.
- Process death/restart does not silently resurrect an authenticated session.
