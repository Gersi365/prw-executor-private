SPAWN ORDERING

The adapter receives:

- an existing std::thread::Scope;
- one already-authenticated AuthenticatedLocalLinuxSession<UnixStream>;
- one already-acquired Phase 075 LocalLinuxWorkerPermit;
- borrowed policy/snapshot context valid for the scope;
- typed Phase 076 worker configuration.

Builder::spawn_scoped is invoked exactly once.

On successful spawn, session and permit move into the scoped closure and the closure runs the Phase 076 worker body exactly once. The caller receives the ScopedJoinHandle and therefore retains explicit join/result authority.

The enclosing Rust thread scope remains the structural lifetime boundary, so the session worker cannot outlive that scope.

VALIDATED BEHAVIOR

Linux runner tests prove:

- the worker-capacity permit remains active while policy evaluation is deliberately held inside the scoped worker;

- the terminal response remains readable and the worker-owned session stream then reaches EOF;
- policy and DNS snapshot data can be borrowed from the surrounding thread-scope environment;
- test synchronization uses only safe Rust atomics/barriers under workspace unsafe_code=forbid.
