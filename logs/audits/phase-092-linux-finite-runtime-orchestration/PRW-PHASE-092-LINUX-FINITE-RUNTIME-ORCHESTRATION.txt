RUNTIME-SPECIFIC SCHEDULING

Phase 092 adds LocalLinuxRuntimeSchedulerContext containing:

- existing Phase 075 worker capacity;
- existing bounded local policy;
- existing local Agent status snapshot;
- existing private-DNS snapshot;
- existing finite worker configuration;
- one Phase 089 completion-wake notifier.

The runtime-specific one-shot scheduling transaction preserves Phase 084 ordering but uses only the Phase 090 completion-wake spawn path.

Ordering remains:

1. acquire capacity permit before accept;
2. return AtCapacity without touching listener when no slot exists;
3. perform one authenticated accept attempt;
4. release permit on NoConnectionReady;
5. create authenticated-stream cancellation authority;
6. compose authenticated session;
7. spawn one scoped worker through spawn_authenticated_session_worker_with_completion_wake(...);
8. register scoped handle and matching cancellation authority.

The pre-existing Phase 084/086 APIs remain intact and are not silently converted to require runtime wake state.

BOUNDED RUNTIME SCHEDULING CYCLE

run_bounded_runtime_scheduling_cycle(...) preserves Phase 085/086 finite semantics while guaranteeing completion-wake workers:

- caller supplies NonZeroUsize attempt budget;
- registry.reap_finished() occurs before every possible schedule;
- shutdown is rechecked before every possible accept;
- first error terminates without scheduler retry;
- AtCapacity terminates current cycle immediately;
- NoConnectionReady terminates current cycle immediately;
- WorkerRegistered may continue only while attempt budget remains;
- report records completions, workers registered, scheduling attempts, and Phase 085-compatible stop reason.

FINITE READINESS + SCHEDULING ORCHESTRATION

run_finite_linux_runtime_orchestration(...) contains no outer loop.

It performs exactly one Phase 091 readiness invocation.

- ShutdownObserved => zero scheduling attempts and immediate return.
- RuntimeWake => zero scheduling attempts and immediate return.
- WaitInterrupted => zero scheduling attempts and immediate return.
- ListenerReady => exactly one caller-bounded runtime-specific scheduling cycle may run.

The scheduling cycle independently rechecks shutdown before every possible accept, preserving a second fail-closed gate after Phase 091 wake-first handling.

SHUTDOWN STATE-BEFORE-WAKE

Phase 092 adds LocalLinuxRuntimeShutdownHandle as a bounded producer helper.

request_shutdown_and_wake() ordering is locked and implemented as:

1. LocalLinuxSchedulerControl::request_shutdown();
2. Phase 089 notifier.notify().

Shutdown state remains committed even if wake notification reports a bounded error.

No OS signal handler or production service-manager source is introduced.

FOCUSED RUNTIME PROOFS

1. COMPLETION-WAKE WORKER REGISTRATION

A listener-ready finite orchestration step registers one worker through the Phase 090 completion-wake path, produces a valid bounded local status response, and later exposes a completion wake with released capacity.

2. COMPLETION WAKE RESTORES CAPACITY FOR THE NEXT CLIENT

The deterministic proof uses capacity one:

- first worker is scheduled;
- capacity is observed full and no completion wake is pending;
- first client is closed;
- Phase 091 waits while no second client is queued and receives the completion wake;
- capacity is observed zero;
- only then is the second client connected and its bounded request written;
- a later finite Phase 092 invocation registers exactly one second completion-wake worker;
- second response validates;
- second completion wake returns capacity to zero.

This proves progress without polling cadence, arbitrary sleep, listener spin, or missed completion wake.

3. SHUTDOWN PREVENTS QUEUED ACCEPT

A client is queued, shutdown state is committed and wake posted, and finite orchestration returns ShutdownObserved with:

- zero scheduling attempts;
- zero workers registered;
- zero active workers.

An explicit later test accept proves the queued client remained in the listener, demonstrating that shutdown orchestration did not consume it.

4. AT-CAPACITY PRESERVES QUEUED CLIENT

With the sole capacity permit held and a client queued, the runtime-specific bounded scheduling cycle:

- performs exactly one attempt;
- returns AtCapacity;
- registers no worker;
- leaves the client queued.

5. EVENTFD COUNTER IS NOT SEMANTIC DATA

Multiple wake notifications may coalesce into one drainable Phase 089 state. The counter is not interpreted as worker-result count, scheduling attempt count, request identity, or protocol data.

PHASE 086 TEST-RACE CORRECTIVE

Phase 092 A01 exposed one latent flaky assumption in the existing Phase 086 test reaps_finished_worker_before_next_schedule_attempt.

The old test waited until LocalLinuxWorkerCapacity::active_workers() == 0 and treated that as proof that ScopedJoinHandle::is_finished() must already be true.

That implication is invalid: worker-owned LocalLinuxWorkerPermit may be dropped during worker-body completion before the scoped thread has necessarily completed the final state transition observed by ScopedJoinHandle::is_finished().

No production Phase 086 or registry semantics were changed.

A test-only #[cfg(test)] method was added:

LocalLinuxScopedWorkerRegistry::has_finished_worker_for_test()

It observes the actual condition used by reap_finished(): retained handle.is_finished().

The existing Phase 086 test now waits for that exact condition and then additionally confirms active worker capacity is zero before calling the bounded cycle.

This corrective changes test synchronization only; it adds no production API or behavior.
