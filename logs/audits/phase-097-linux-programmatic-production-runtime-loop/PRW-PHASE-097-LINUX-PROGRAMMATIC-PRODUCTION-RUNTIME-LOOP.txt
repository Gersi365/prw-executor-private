LONG-RUNNING LOOP SEMANTICS

The loop owns one `std::thread::scope`, one scoped worker registry, and one fixed-size saturating counter aggregate for its lifetime.

Every iteration performs exactly one already-validated Phase 092 finite orchestration invocation.

Successful dispositions:
- `ShutdownObserved` => terminal `ShutdownRequested`;
- `RuntimeWake` => return to readiness;
- `WaitInterrupted` => return to readiness without hidden syscall retry;
- all successful `Scheduling(...)` outcomes => return to capacity-aware blocking readiness.

Error dispositions:
- same-UID peer-authorization rejection => record bounded rejection evidence and continue;
- every other initial readiness/scheduling error => retain exact fatal classification and fail-stop.

No sleep, periodic timeout, busy poll, retry cadence, or unbounded error backoff is introduced.

PROCESS-LIFETIME EVIDENCE

Phase 097 extends the fixed-size Phase 095 counters so scheduling-error paths retain:
- the listener-ready readiness step;
- scheduling attempts including the failed attempt;
- workers registered earlier in the failed cycle;
- worker completions reaped before the error.

Final joined worker completions are also added to the saturating completion counter.

Only terminal cancellation outcomes and terminal joined completions remain vectors; both are bounded by configured maximum worker capacity.

TERMINAL TRANSACTION

On shutdown or fatal failure:
1. no later loop iteration is entered;
2. `registry.cancel_all()` issues terminal socket shutdown to retained workers;
3. `registry.join_all()` joins/classifies all remaining workers;
4. final completions are added to bounded counters;
5. the scoped worker lifetime exits;
6. Phase 096 performs exact listener/socket cleanup;
7. loop evidence and cleanup evidence are combined into `LocalLinuxProductionRuntimeTerminalReport`.

Listener cleanup failure remains independent from and cannot overwrite the original shutdown/fatal reason.

PROGRAMMATIC SHUTDOWN SEAM

`run_local_linux_production_runtime_from_env(...)` remains callable below `main.rs`.

After lifecycle assembly and before the blocking loop starts, its `on_started` callback receives a cloneable `LocalLinuxRuntimeShutdownHandle`. The handle commits monotonic shutdown state before posting Phase 089 runtime wake.

This is intentionally the deterministic pre-signal control seam. OS signal integration remains Phase 098 work.
