ARCHITECTURAL DECISION

Production private-key signing does NOT get added to the existing prw-device-identity verifier crate.

A new narrow workspace crate is locked:
crates/prw-device-identity-signer

Rationale:
- preserves the verifier crate's existing public/private-key separation;
- makes private-key dependency reachability explicit in Cargo dependency graphs;
- allows Agent/control-plane components that only verify identities to avoid importing signer APIs;
- gives Ubuntu private-key parsing/signing lifecycle its own audit boundary;
- prevents future Android Keystore signing from being forced through an exportable-PKCS#8 implementation;
- allows systemd credential acquisition to remain a separate adapter/lifecycle concern.

The new crate is an internal PRW implementation boundary, not a generic cryptographic toolkit.

LOCKED CRATE RESPONSIBILITY

prw-device-identity-signer may own only:
- parsing/loading the locked Ubuntu PKCS#8 v1 DER P-256 credential into the locked signing provider;
- deriving the canonical X.509 SPKI public identity from the loaded key;
- validating that a typed EnrollmentRequest public identity exactly matches the signer key;
- constructing the canonical Phase 115 enrollment PoP message through the existing control-plane encoder;
- creating a DER ECDSA-Sig-Value signature with P-256/SHA-256;
- returning the existing typed EnrollmentProofOfPossession value;
- bounded error classification without private material.

It must not own:
- systemd credential path discovery;
- XDG state file creation/read/write;
- encrypted credential provisioning;
- service-unit configuration;
- account authentication;
- enrollment approval;
- networking/wire protocol;
- transport cryptography;
- arbitrary signing;
- key export/backup APIs.

LOCKED UBUNTU LOAD BOUNDARY

The initial Ubuntu signer constructor/load boundary consumes the plaintext bytes of the Phase 119-locked payload:
PKCS#8 v1 DER containing an ECDSA P-256 private key.

The source of those bytes is outside signer core. A later custody adapter reads the already-decrypted named systemd credential and passes a bounded buffer to signer construction.

The signer constructor must:
1. reject empty input;
2. impose an explicit small upper bound before provider parsing;
3. parse only the locked P-256/SHA-256 signing profile;
4. derive canonical X.509 SPKI public identity;
5. retain the provider key object, not a second long-lived plaintext PKCS#8 copy;
6. never expose the loaded private bytes through Debug, Display, errors, accessors, serialization, IPC, or logs.

INITIAL PRIVATE CREDENTIAL SIZE BOUND

Phase 121 must use a bounded input size rather than accepting unbounded credential bytes.

Locked initial maximum plaintext PKCS#8 credential length:
4096 bytes.

Rationale:
- far above the expected P-256 PKCS#8 v1 payload size;
- small enough to bound memory/parsing exposure;
- leaves implementation headroom without coupling security behavior to one provider's current exact encoding size.

Input length must be 1..=4096 bytes.

PRIVATE BYTE LIFETIME / ZEROIZATION

The custody adapter owns the incoming decrypted credential buffer until it transfers/borrows it for signer construction.

Phase 121 must ensure any PRW-owned mutable buffer containing plaintext private credential bytes is zeroized on drop/after successful parsing.

Preferred implementation mechanism:
- direct exact-pinned zeroize dependency already resolved in the workspace dependency graph where practical;
- use a zeroizing owner for temporary PKCS#8 bytes in tests/adapter-facing APIs;
- do not implement custom unsafe memory wiping.

The provider's internal key object lifecycle is delegated to the locked provider; PRW must not add a second raw private-key representation to the signer object.

The signer type's Debug output must not include private key material.

LOCKED PUBLIC SIGNER API SHAPE

The crate public API may expose a provider-specific Ubuntu signer type or an equivalently narrow type, conceptually:

UbuntuEnrollmentSigner

Required operations:

1. construction from the bounded PKCS#8 v1 DER custody payload;
2. public_identity() -> canonical typed PublicIdentityMaterial;
3. sign_enrollment_proof(request, challenge) -> typed EnrollmentProofOfPossession.

The exact Rust names may be adjusted by rustfmt/Clippy/API ergonomics in Phase 121, but the security semantics are fixed by this report.

GENERIC SIGNING IS FORBIDDEN

The public crate API must not expose any method semantically equivalent to:
- sign(message: &[u8]);
- sign_digest(...);
- sign_arbitrary(...);
- raw provider key access;
- private_key();
- export_pkcs8();
- export_secret();

Provider generic sign functions may be invoked only inside the crate-private implementation after typed PRW checks and canonical message construction.

TYPED SIGNING INPUT

The signing operation accepts:
- a typed EnrollmentRequest;
- a typed EnrollmentProofChallenge.

The caller does not supply raw message bytes.

Required checks before provider signing:
1. request.enrollment_id exactly equals challenge.enrollment_id;
2. request.public_identity exactly equals the signer's canonical public identity;
3. request identity profile is the locked P-256/SPKI profile;
4. canonical message construction through encode_enrollment_proof_message succeeds under all existing bounds;
5. only then may the crate-private provider call sign the internally constructed bytes.

Challenge lifetime verification remains verifier/server policy. The device signer need not trust or enforce the server clock. It signs the exact typed challenge nonce supplied by the server after enrollment-id binding checks.

OUTPUT

Successful signing returns an EnrollmentProofOfPossession whose:
- enrollment_id equals request/challenge enrollment id;
- nonce equals the exact challenge nonce;
- signature is DeviceIdentityAlgorithm::EcdsaP256Sha256;
- signature encoding is DeviceIdentitySignatureEncoding::EcdsaSigValueDer.

The signer must not approve enrollment or mutate server challenge state.

PUBLIC IDENTITY CONSISTENCY

A signer loaded from a private credential derives its own canonical public identity.

Signing MUST fail if the EnrollmentRequest declares any different public identity, including:
- different P-256 key;
- altered SPKI bytes;
- different algorithm/encoding metadata.

This prevents an already-loaded signer from becoming a signing oracle for an enrollment snapshot that claims another identity.

The equality check occurs before signing.

ANDROID COMPATIBILITY

The Phase 120 Ubuntu signer crate does not become the Android private-key implementation.

Android's Phase 116 lock remains:
- private P-256 key generated and retained in Android Keystore;
- no private-key export to Rust/PKCS#8;
- signing delegated to Keystore-backed Signature operation.

Android should implement the same semantic typed operation:
- derive/report its canonical public identity;
- verify EnrollmentRequest identity binding;
- locally construct the canonical enrollment PoP message;
- sign only that message;
- return the typed proof.

A later bridge/API phase may share provider-neutral typed request/result semantics, but must not force Android through UbuntuEnrollmentSigner or an exportable private-key constructor.
