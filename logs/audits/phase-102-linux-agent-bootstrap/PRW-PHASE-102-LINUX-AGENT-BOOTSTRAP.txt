PURPOSE

Phase 102 wires the already-validated Phase 098 signal-aware production-local runtime into the real `prw-agent` executable while preserving the Phase 101 narrow public boundary, fixed bounded initial profile, bounded stderr contract, simple success/failure exit mapping, and explicit separation from systemd packaging/activation.

PHASE 101 CONTRACT PRESERVED

The integrated initial profile is exactly:

- worker capacity: 2;
- Unix listener backlog: 8;
- scheduling attempts per listener-ready cycle: 2;
- requests per session: 1;
- read I/O budget: 2 seconds;
- write I/O budget: 2 seconds;
- policy: `BoundedLocalReadPolicy::allow_local_reads()`;
- status snapshot: immutable `Ready`;
- private DNS: `PrivateDnsConfig::default()` projected into the bounded local snapshot.

No configuration-file parser, CLI override, live reload, environment-based capability expansion, or mandatory private DNS was introduced.

PUBLIC API BOUNDARY

Phase 102 adds one Linux-only public bootstrap facade:

`prw_agent::linux_bootstrap`

The existing Linux implementation graph remains crate-private:

`pub(crate) mod linux_identity`

The facade maps internal runtime evidence into bounded bootstrap-level terminal/startup classifications and fixed-size counters. It does not expose the Phase 057-098 lifecycle/socket/readiness/signal/scheduling/worker object graph.

THIN BINARY BOUNDARY

`crates/prw-agent/src/main.rs` now performs only:

1. one call to `prw_agent::linux_bootstrap::run()`;
2. one bounded stderr startup-failure or terminal-summary record;
3. the Phase 101 success/failure `ExitCode` mapping.

The binary does not implement its own socket creation, signal handling, worker threads, scheduling loop, configuration parser, systemd behavior, private-DNS mutation, or remote/public networking.

EXIT CONTRACT

Success requires all of:

- normal handled terminal reason: SIGTERM, SIGINT, or clean programmatic shutdown;
- clean listener/socket cleanup;
- successful restoration of the prior runtime-thread signal mask.

Every startup/lifecycle/runtime fatal class, cleanup failure, or signal-mask restoration failure maps to failure.

STDERR CONTRACT

The binary emits only one bounded record per tested lifetime outcome:

- one startup-failure record if startup fails; or
- one terminal summary after runtime return.

The validated terminal output contains bounded high-level classifications/counters only and does not expose request payload data.

REAL STANDALONE BINARY PROOF

Committed proof:

`crates/prw-agent/tests/phase_102_binary_bootstrap.rs`

The test launches the actual Cargo-built `prw-agent` executable as child processes. It does not substitute direct library calls for the binary boundary.

The proof is sequential and uses isolated temporary XDG runtime roots.

Validated scenario A — SIGTERM:

- real Agent binary starts under valid temporary XDG root;
- Unix Agent socket becomes connectable;
- SIGTERM is delivered to the child PID;
- binary exits successfully;
- stderr classifies `terminal=sigterm`, `exit=success`, clean cleanup, restored signal mask;
- socket pathname is absent after exit.

Validated scenario B — SIGINT:

- same binary-level flow using SIGINT;
- successful handled exit;
- clean listener/socket cleanup;
- restored signal mask;
- no stale socket pathname.

Validated scenario C — real same-UID local request:

- test connects through the real Unix socket;
- writes a real `GetAgentStatus` request frame with the public request writer;
- reads/decodes the real successful status response with the public response reader;
- request ID correlation is preserved;
- runtime state is `Ready`;
- protocol version is supported;
- child then terminates cleanly via SIGTERM.

Validated scenario D — second-instance exclusion:

- first Agent remains active under one temporary XDG runtime root;
- second Agent against the same root exits failure with `kind=already_running`;
- second process restores its signal mask;
- first process remains functional and answers another real status request;
- first process then terminates cleanly and removes its socket.

Validated scenario E — missing runtime root:

- child starts with `XDG_RUNTIME_DIR` removed;
- startup fails deterministically with `kind=runtime_root`;
- process maps to failure exit;
- signal mask is restored.

Validated scenario F — wrong-mode runtime root:

- temporary root mode is changed to 0755;
- startup fails with `kind=runtime_root` before usable listener activation;
- failure exit is returned;
- signal mask is restored;
- no Agent socket pathname is left behind.
