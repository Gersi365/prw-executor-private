LOCKED/VALIDATED READINESS SEMANTICS

- terminal shutdown is checked before blocking;
- Phase 089 runtime wake is always armed for PollFlags::IN;
- listener readiness is armed only while active_workers() < max_workers();
- normal wait uses poll(..., None), with no periodic timeout;
- poll EINTR is surfaced as WaitInterrupted and is not retried internally;
- zero or contradictory ready-count results fail closed;
- ERR, HUP and NVAL fail closed for either descriptor;
- unsupported revents bits fail closed;
- runtime wake is processed before simultaneous listener readiness;
- wake is drained before listener dispatch eligibility is returned;
- wake processing calls registry.reap_finished() and returns observed completion evidence;
- shutdown is re-observed after wake processing;
- capacity is re-observed before simultaneous listener readiness can be returned;
- listener-only readiness rechecks shutdown and capacity before returning ListenerReady.

BUSY-LOOP PREVENTION PROOF

A focused real-kernel test recreates the Phase 087-A01 risk state:

- worker capacity max = 1;
- the sole capacity permit is held;
- an additional client is queued on the nonblocking Unix listener.

With full capacity, Phase 091 omits the listener from the poll set. A controlled runtime wake returns RuntimeWake with listener_armed=false rather than being immediately driven by the still-readable queued listener.

After the permit is released, a second finite invocation arms the listener and observes the still-queued client as ListenerReady.

This proves the Phase 087-A01 queued-listener/full-capacity spin is structurally excluded by the Phase 091 wait-set rule.

WAKE-FIRST PRECEDENCE PROOF

A focused test makes both wake and listener readable before the wait. Phase 091 drains the runtime wake first, re-observes runtime state, and only then returns ListenerReady while capacity/shutdown permit it. A subsequent wake drain returns WouldBlock, proving the wake was consumed before listener outcome exposure.

COMPLETION-EVIDENCE PROOF

A focused test registers an already-finished scoped worker, posts a completion-style runtime wake, and proves wake handling reaps/classifies that worker into LocalLinuxScopedWorkerCompletion evidence and empties the registry entry.

Phase 091 intentionally treats wake-time reaping as an observation attempt: a completion wake can race the final transition of ScopedJoinHandle::is_finished(). Therefore a wake does not claim its causal worker is immediately joinable. Final ownership remains bounded by later reap points or shutdown join_all().

POLL CLASSIFICATION PROOFS

Deterministic tests prove:

- Errno::INTR => WaitInterrupted;
- other poll errno => WaitFailed;
- Ok(0) => InvalidWaitReturn;
- impossible ready count => InvalidWaitReturn;
- wake ERR => WakeDescriptorFailed;
- listener HUP => ListenerDescriptorFailed;
- unsupported wake OUT => InvalidWakeReadiness;
- IN readiness => valid;
- empty revents => not-ready.
