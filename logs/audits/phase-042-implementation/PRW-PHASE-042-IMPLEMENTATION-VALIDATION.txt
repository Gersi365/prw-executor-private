LOCKED ORDERING

1. reject an already-WritePoisoned response-write state before consuming input;
2. read and fully decode exactly one current Request;
3. evaluate the caller-supplied policy context only after successful Request decoding;
4. build one correlated terminal response frame in memory;
5. validate/write it through the Phase 041 guarded writer.

PRE-POISONED POSTCONDITION

When response-write state is already poisoned:
- zero input reads;
- zero policy calls;
- zero output writes.

INVALID REQUEST POSTCONDITION

Malformed/unknown Request input:
- stops before policy response construction;
- performs zero policy calls for decode failures;
- performs zero response writes;
- leaves the response-write state Healthy.

VALID REQUEST POSTCONDITION

- Allow -> existing command-specific successful response is written;
- Deny -> correlated Unauthorized terminal Error is written;
- successful response write leaves response-write state Healthy;
- response write failure poisons state before return.
