TYPE-STATE ORDERING

The validated Linux local socket lifecycle now includes:

BoundAgentSocket
  -> ListeningAgentSocket
  -> AcceptReadyAgentSocket
  -> one-shot authenticated accepted connection

A plain Phase 068 ListeningAgentSocket exposes no accept operation through the Phase 070 API.

READINESS TRANSITION

prepare_accept_ready_agent_socket:

- consumes a Phase 068 ListeningAgentSocket;
- reads current descriptor status flags with rustix::fs::fcntl_getfl;
- sets O_NONBLOCK with rustix::fs::fcntl_setfl while preserving existing status flags when needed;
- reads status flags again;
- returns AcceptReadyAgentSocket only after O_NONBLOCK is verified;
- on transition failure returns the original listening object together with a bounded readiness-transition error so caller cleanup ownership is preserved.

ONE-SHOT ACCEPT

AcceptReadyAgentSocket::try_accept_authenticated:

- performs at most one rustix::net::accept_with call per invocation;
- requests SocketFlags::CLOEXEC for the accepted descriptor;
- treats EAGAIN/EWOULDBLOCK as the normal NoConnectionReady outcome;
- maps other kernel accept failures to a bounded AcceptFailed error;
- converts a successfully accepted descriptor to the connected Unix stream type only inside the crate-internal Linux boundary;
- immediately invokes Phase 059 AuthenticatedLocalLinuxConnection::try_new;
- therefore Linux SO_PEERCRED and exact same-effective-UID authorization occur before any PRW application-protocol byte is read;
- returns only the authenticated wrapper on success;
- explicitly drops the rejected connected stream before returning a bounded peer-authorization failure.

ACCEPTED STREAM SEMANTICS

The listener is nonblocking after the Phase 070 readiness transition.

The accepted connected stream requests close-on-exec but not accepted-stream NONBLOCK. Linux runner validation proved:

- accepted descriptor has FD_CLOEXEC;
- accepted stream does not have O_NONBLOCK;
- this preserves the existing blocking std::io::Read/Write semantics expected by Phase 059/060.

VALIDATED SECURITY ORDERING

Temporary Linux runner tests prove:

- the accept-ready listener has O_NONBLOCK;
- an empty connection queue returns NoConnectionReady without blocking;
- a local same-UID client is accepted and authenticated;
- accepted descriptor is CLOEXEC and remains blocking;
- sentinel bytes written before accept/authentication remain unread through the authentication boundary and are recoverable only after successful authenticated wrapping;
- peer UID reported by the authenticated wrapper equals the Agent effective UID;
- accepting one client does not consume the listener lifecycle and a later client can also be accepted;
- after sequential accepts, an empty queue again returns NoConnectionReady;
- Phase 065 instance-lock contention remains AlreadyRunning while the accept-ready listener is alive;
- existing Phase 067/068 cleanup remains authoritative.
