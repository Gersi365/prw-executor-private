LOCKED SCHEDULING SEMANTICS

One bounded cycle:

1. receives a caller-supplied NonZeroUsize attempt budget;
2. calls registry.reap_finished() before every potential scheduling attempt;
3. checks the shared monotonic shutdown flag after reaping and before Phase 084;
4. performs no accept/spawn when shutdown is already requested;
5. performs at most one Phase 084 transaction per consumed attempt;
6. terminates immediately on AtCapacity or NoConnectionReady instead of busy-retrying;
7. continues after WorkerRegistered only while caller budget remains;
8. terminates on the first bounded Phase 084 error without retry;
9. returns structured completion, registration, attempt-count, and stop-reason evidence.

SCHEDULER CONTROL

LocalLinuxSchedulerControl is backed by Arc<AtomicBool>.

- new/default begins with shutdown not requested;
- request_shutdown() is a monotonic one-way transition;
- is_shutdown_requested() is observation only;
- no reset/resume operation exists;
- active worker cancellation remains the separate Phase 082 boundary.

VALIDATED BEHAVIOR

Linux runner tests prove:

- shutdown requested before cycle execution performs zero scheduling attempts and leaves a queued client unconsumed;
- NoConnectionReady terminates after exactly one attempt even when a larger budget is available;
- AtCapacity terminates after one attempt without consuming a queued connection;
- the exact caller attempt budget limits multiple queued worker registrations;
- a finished worker is reaped before the next scheduling attempt and its completion is returned as cycle evidence;
- existing worker capacity, cancellation, join, listener cleanup, and request/response behavior remain compatible with the bounded cycle.
