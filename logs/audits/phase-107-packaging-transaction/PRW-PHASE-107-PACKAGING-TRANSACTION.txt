PREFLIGHT CONTRACT

A future installer must fail before replacement unless the target is absent or can be established as a PRW-managed prior package payload.

Unknown/foreign files at the locked destinations must not be silently overwritten.

Package-manager database integration, signed payload identity, release signatures, and reproducible release artifact verification remain later release-packaging work.

FRESH INSTALL CONTRACT

1. validate complete binary and exact unit payload before destination mutation;
2. stage both payloads privately on the destination filesystem;
3. set final modes;
4. set final ownership in the future privileged installer;
5. validate staged hashes/metadata;
6. atomically replace executable destination;
7. atomically replace unit destination;
8. validate final bytes/modes/paths and absence of activation artifacts;
9. remove staging/rollback material only after postconditions pass.

A failure after partial replacement must remove transaction-created files for a fresh install.

UPGRADE CONTRACT

Before replacement, preserve exact prior PRW-managed bytes and relevant metadata for both destinations.

Both new payloads must be staged and validated before either destination replacement.

A failure after only one destination is replaced must restore both destinations to the exact pre-upgrade payload/mode state.

Live-service upgrade behavior is not part of Phase 107. Stop/reload/restart of an activated service remains a later activation/upgrade gate.

REMOVE CONTRACT

For the non-activated package case:

- preserve exact managed payloads until postconditions pass;
- remove the service unit;
- remove the executable;
- remove the package-owned executable directory only if empty;
- restore exact prior payloads on intermediate failure;
- do not alter unrelated content.

Activation-aware uninstall is deferred. Any future enablement/start artifacts must be owned and rolled back by the later activation transaction that creates them.
