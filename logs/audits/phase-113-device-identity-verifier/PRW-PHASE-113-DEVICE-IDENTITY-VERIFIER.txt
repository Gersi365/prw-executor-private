PROVIDER-NEUTRAL PUBLIC API

The production public verification operation is:

verify_device_identity_signature(public_identity, message, signature)
    -> Result<(), DeviceIdentityVerificationError>

Its public inputs are existing PRW-owned typed values:
- PublicIdentityMaterial;
- DeviceIdentitySignature;
- caller-supplied message bytes.

Its public error boundary is PRW-owned and bounded:
- UnsupportedProfile;
- InvalidPublicKey;
- NonCanonicalPublicKeyEncoding;
- InvalidSignature.

No AWS-LC type appears in the public function signature or public error type. Provider-specific types remain implementation details inside prw-device-identity.

LOCKED PROFILE IMPLEMENTATION

The production verifier preserves the existing Phase 003/004 profile exactly:
- ECDSA over NIST P-256 with SHA-256;
- DER X.509 SubjectPublicKeyInfo public key;
- id-ecPublicKey algorithm identifier;
- secp256r1 / NIST P-256 named curve;
- DER RFC 3279 ECDSA-Sig-Value signature.

The production implementation deliberately narrows provider parser flexibility:
1. validate explicit PRW algorithm and encoding identifiers;
2. parse the public key with AWS-LC's P-256/SHA-256 verification profile;
3. re-serialize the parsed public key as X.509 SubjectPublicKeyInfo DER;
4. require exact byte-for-byte equality with the original PRW public-key bytes;
5. only after canonical equality, verify the DER ECDSA signature.

This prevents raw SEC1 or other alternate encodings accepted for provider convenience from becoming valid PRW protocol representations.
