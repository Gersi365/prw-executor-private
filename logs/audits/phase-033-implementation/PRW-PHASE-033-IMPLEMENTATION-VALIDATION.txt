LOCKED ORDERING

For one typed local read-only Request:
1. build the complete validated Phase 031 Request frame;
2. register the request ID in the bounded Phase 013 outstanding-request tracker;
3. only after successful registration, begin generic frame writing;
4. do not flush implicitly.

REGISTRATION FAILURE SEMANTICS

If request registration fails because the ID is already outstanding or the tracker is full:
- zero bytes are written;
- pre-existing tracker state is preserved;
- the caller receives a typed Register failure.

WRITE FAILURE SEMANTICS

If generic frame writing fails after successful registration:
- the request ID remains outstanding;
- no tracker rollback occurs;
- request-ID reuse is not permitted merely because the write returned an error;
- the stream is treated as potentially desynchronized because a prefix of the frame may already have been accepted by the writer.
