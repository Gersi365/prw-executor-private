Phase 057 Linux Local Peer Identity Adapter

STATUS: PASS / IMPLEMENTED_AND_VALIDATED

PURPOSE

Introduce the first PRW source use of the locked rustix 1.1.4 platform provider, limited to read-only Linux identity operations over an already-existing file descriptor.

IMPLEMENTED

Linux-only crate-internal module:
`crates/prw-agent/src/linux_identity.rs`

The adapter provides:
- Agent effective UID through `rustix::process::geteuid()`;
- Linux kernel peer PID/UID/GID through `rustix::net::sockopt::socket_peercred` (`SO_PEERCRED`);
- a PRW-local typed `LocalLinuxPeerCredentials` record;
- a bounded `PeerCredentialLookup` failure classification.

No rustix-specific credential type is exposed outside the crate-internal platform module.

SECURITY BOUNDARY

Phase 057 retrieves identity only. It does not authorize a peer and performs no application-protocol read or write.

The locked future ordering remains:

peer credentials -> same-effective-UID decision -> only then application Request processing.

TEST STRATEGY

The Linux test uses only `std::os::unix::net::UnixStream::pair()` as an anonymous already-connected descriptor source.

It validates that kernel-reported credentials on both pair endpoints match:
- the current process PID;
- the Agent effective UID;
- the process effective GID.

No filesystem socket pathname, listener, bind, accept, or XDG runtime path is involved.
