TEST PROFILE

The Phase 119 harness contains exactly six focused tests.

1. pkcs8_v1_round_trip_preserves_canonical_public_identity
- generates a disposable P-256 private key as PKCS#8;
- reloads it with the locked P-256/SHA-256 ASN.1 signing algorithm;
- derives canonical X.509 SPKI DER;
- reserializes as PKCS#8 v1;
- reloads again;
- proves the canonical public identity is unchanged.

2. asn1_der_signature_verifies_through_production_verifier
- signs a disposable test message with the reloaded P-256 key;
- wraps the provider signature in the existing typed DeviceIdentitySignature profile;
- proves the output is ASN.1 DER shaped;
- verifies through verify_device_identity_signature, the existing production verifier.

3. full_enrollment_pop_from_reloaded_pkcs8_verifies_and_consumes_once
- constructs an actual typed EnrollmentRequest;
- constructs the exact Phase 115 canonical PoP message;
- signs it with the reloaded disposable PKCS#8 key;
- verifies through verify_enrollment_proof;
- proves successful verification consumes the challenge;
- proves the same proof cannot be accepted a second time.

4. signature_from_different_private_key_is_rejected_without_consuming_challenge
- binds the enrollment request to key A;
- signs the exact canonical message with independent key B;
- requires InvalidSignature;
- proves the challenge remains unconsumed.

5. signature_over_mutated_canonical_message_is_rejected_without_consuming_challenge
- constructs the correct canonical message;
- mutates one message byte before signing;
- submits the resulting signature against the unmodified server-side snapshot;
- requires InvalidSignature;
- proves the challenge remains unconsumed.

6. truncated_pkcs8_is_rejected
- truncates a generated PKCS#8 private-key document;
- requires aws-lc-rs private-key import to fail closed.

PRIVATE PAYLOAD FORMAT LOCK

Phase 119 locks the initial Ubuntu plaintext device-identity private credential payload as:

PKCS#8 v1 DER

The payload contains an ECDSA P-256 private key compatible with:
ECDSA_P256_SHA256_ASN1_SIGNING

This PKCS#8 DER payload is the plaintext value protected by the outer systemd encrypted credential container locked in Phase 118.

The persistent file is therefore not plaintext PKCS#8. The persistent PRW file remains a systemd encrypted credential blob. PKCS#8 bytes are exposed only inside the custody/signing boundary after successful systemd credential decryption/delivery.

PUBLIC IDENTITY DERIVATION

The public identity associated with the private credential is derived from the reloaded key as canonical X.509 SubjectPublicKeyInfo DER.

It must be wrapped as:
- DeviceIdentityAlgorithm::EcdsaP256Sha256;
- DeviceIdentityPublicKeyEncoding::SubjectPublicKeyInfoDer.

The Phase 119 round-trip proves the public identity is stable across PKCS#8 v1 serialization and reload.

SIGNATURE FORMAT LOCK CONFIRMATION

The signer algorithm remains:
ECDSA_P256_SHA256_ASN1_SIGNING

The produced signature is represented through:
- DeviceIdentityAlgorithm::EcdsaP256Sha256;
- DeviceIdentitySignatureEncoding::EcdsaSigValueDer.

The existing production verifier accepts the signature directly. No transcoding from a fixed-width r||s format is required or permitted at the PRW signing boundary.

SIGNING SAFETY BOUNDARY

Phase 119 does not expose provider EcdsaKeyPair::sign as a PRW production public API.

The provider's generic message-sign function is exercised only inside this compatibility test harness.

The production PRW signer remains required to expose only a typed enrollment-PoP operation that:
1. accepts typed enrollment/challenge context;
2. constructs the canonical Phase 115 message internally;
