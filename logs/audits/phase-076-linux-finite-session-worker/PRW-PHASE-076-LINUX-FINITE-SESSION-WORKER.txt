Implement the finite authenticated-session worker body required by the Phase 072 runtime-processing bounds while still spawning no OS thread and accepting no connection.

OWNERSHIP AND LIFECYCLE

run_authenticated_session_worker consumes:

- one AuthenticatedLocalLinuxSession<UnixStream>;
- one non-cloneable Phase 075 LocalLinuxWorkerPermit;
- caller-supplied policy and snapshots;
- one typed LocalLinuxSessionWorkerConfig containing the finite Request count and Phase 074 read/write I/O budgets.

The session and permit are never returned to the caller.

The permit remains live through the entire worker-body call and releases exactly one worker slot by RAII on every normal return and unwind.

The session stream is dropped when the worker body returns. Runtime orchestration therefore cannot resume the same connection with a fresh Request budget.

PROCESSING SEMANTICS

For every permitted Request:

1. invoke Phase 074 process_one_with_deadlines;
2. create a fresh absolute Request-read deadline;
3. use an independent deferred terminal-response-write deadline;
4. increment the completed-response count only after ResponseWritten;
5. clean EOF terminates normally;
6. the first processing failure terminates with the count of previously completed responses;
7. consuming the final permitted Request terminates with RequestBudgetExhausted.

TYPED CONFIGURATION

LocalLinuxSessionWorkerConfig groups:

- maximum Request count;
- per-Request read I/O budget;
- per-Request response-write I/O budget.

This keeps the worker entry point bounded without lint allowances and prepares the values to be supplied by a later runtime configuration boundary. No production values are selected by this phase.

VALIDATED BEHAVIOR

Linux runner tests prove:

- the Phase 075 worker permit remains active during policy evaluation;
- Request-budget exhaustion writes the permitted terminal response, closes the session stream, and releases the permit;
- the client can read the final response and then observes stream EOF;
- clean peer EOF releases the permit without policy evaluation;
- an idle peer reaches the Phase 074 Request-read deadline;
- read-deadline failure releases the permit and reports zero prior responses when no Request completed.
