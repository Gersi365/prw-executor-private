REMAINING HARD BLOCKERS

The blockers from Phase 014 are now concentrated in the platform/security and pathname-lifecycle layer:

1. SAFE SYSCALL PROVIDER LOCK
- select and lock one safe wrapper/provider compatible with workspace unsafe_code = "forbid";
- verify exact crate/version policy and minimal feature set;
- verify stable Linux SO_PEERCRED support;
- verify no-follow/stat/unlink primitives needed by the final pathname lifecycle.

2. XDG RUNTIME-DIRECTORY SECURITY VALIDATION
- absolute-path and environment validation;
- current-user ownership validation;
- required 0700 access-mode validation;
- fail closed with no weaker fallback.

3. PRW RUNTIME SUBDIRECTORY LIFECYCLE
- create/validate $XDG_RUNTIME_DIR/private-remote-workspace;
- enforce expected owner/type/mode;
- avoid following attacker-controlled final components.

4. STALE SOCKET / SINGLE-INSTANCE ALGORITHM
- classify missing path, live Agent, stale socket, symlink, non-socket object, wrong owner, permission failure, and race/change cases;
- define whether/how a connect probe participates;
- prove conditions under which unlink is permitted;
- avoid naive "exists => unlink" behavior.

5. BIND / POST-BIND VALIDATION / CLEANUP
- bind pathname socket;
- establish 0600 mode under an explicit strategy;
- validate resulting object type/owner/mode;
- define cleanup after partial startup failure and orderly shutdown.

6. ACCEPTED-PEER AUTHENTICATION ORDER
- accept connection;
- retrieve kernel-reported SO_PEERCRED;
- compare peer UID to the Agent/local policy UID;
- reject mismatch before any application-protocol byte is read;
- only then pass the authenticated stream/policy context into the already validated Phase 052 generic connection lifecycle.

7. PROCESS/LISTENER LIFETIME
- second-instance behavior;
- orderly and unclean termination behavior;
- socket-path cleanup policy;
- integration with the future daemon/service lifecycle without activating it prematurely.

IMPORTANT AUTHENTICATION GAP

The current generic pipeline accepts a caller-supplied PolicyEvaluator and its contracts explicitly assume an already authenticated policy context. Phase 052 therefore must not be wired directly to an accepted UnixStream before peer authentication exists.

The future runtime adapter must make the sequence explicit:

accept -> kernel peer credentials -> same-UID authorization -> construct/select authenticated policy context -> invoke bounded generic connection processing.

No policy evaluator is a substitute for SO_PEERCRED authentication.
