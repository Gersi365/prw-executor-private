IMPLEMENTED BOUNDARY

Phase 010 introduces a pure in-memory relationship between a validated local IPC header and its opaque payload.

LocalIpcPayload:
- owns opaque bytes;
- validates that the byte length can be represented by the protocol u32 length field;
- validates that the length does not exceed the Phase 007 1 MiB global payload ceiling;
- permits zero-length payloads;
- exposes borrowed bytes and ownership recovery;
- performs no deserialization.

LocalIpcFrame:
- couples one validated LocalIpcFrameHeader with one bounded LocalIpcPayload;
- requires header.payload_length == payload.len;
- rejects mismatch explicitly;
- never truncates, pads, ignores trailing bytes, or silently rewrites header metadata.

EXPLICIT ALLOCATION LIMITATION

The Phase 010 payload constructor receives an already allocated Vec<u8>. Therefore the phase does not claim to prevent an upstream caller from allocating excessive storage before invoking the constructor.

A future stream-reader boundary must validate the Phase 009 header and its 1 MiB bound before allocating or extending receive storage.
